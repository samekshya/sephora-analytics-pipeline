# Diagrams

Three diagrams, generated by [`build_diagrams.py`](build_diagrams.py) rather than drawn in a
tool. The row counts on them are the measured ones from `../00_project_checkpoint.md` §7, so a diagram that
disagrees with the warehouse is a bug in one of the two — not a matter of the picture being
out of date.

| File | Shows | Used by |
|---|---|---|
| `architecture.*` | CSV → OLTP → warehouse → dashboard, with the Airflow task chain beneath | `README.md`, deck slide 6 |
| `oltp_er.*` | The nine `3nf` tables and their foreign keys | `README.md`, deck slide 4 |
| `star_schema.*` | `fact_reviews`, its five dimensions, and `dim_brand` snowflaked off `dim_product` | `README.md`, deck slide 5 |

Each is emitted as **SVG** — what the deck embeds, so it stays sharp at any projector
resolution — with a **PNG** raster beside it for Markdown that cannot render SVG reliably.

## Regenerating

```powershell
py .\docs\diagrams\build_diagrams.py       # writes the three SVGs
Copy-Item .\docs\diagrams\*.svg .\presentation\assets\ -Force
```

The PNGs are rasterized from the SVGs with headless Chrome at 2× scale. Chrome writes the
file asynchronously and will not screenshot a `file://` URL, so serve the repo first and wait
on the process:

```powershell
Start-Process py -ArgumentList '-m','http.server','8778','--bind','127.0.0.1'
$chrome = "$env:ProgramFiles\Google\Chrome\Application\chrome.exe"
$sizes  = @{ architecture = '1840,748'; oltp_er = '1500,852'; star_schema = '1440,1082' }
foreach ($n in $sizes.Keys) {
    Start-Process $chrome -Wait -NoNewWindow -ArgumentList @(
        '--headless=new', '--disable-gpu', '--hide-scrollbars',
        '--force-device-scale-factor=2', "--window-size=$($sizes[$n])",
        '--virtual-time-budget=5000', "--screenshot=docs\diagrams\$n.png",
        "http://127.0.0.1:8778/docs/diagrams/$n.svg")
}
```

The window size must match the SVG's own dimensions, which `build_diagrams.py` prints when it
runs. A mismatch crops the diagram rather than scaling it.

## Editing

Layout is computed, not hardcoded: `entity_height()` derives a box's height from its field
list, and boxes are positioned relative to each other, so adding a column to a table moves
what needs to move. Two things are worth knowing before changing them:

- The **vertical gap** in `star_schema()` is fixed at 100px so the `1` and `N` labels on the
  customer and date links always have clear air. Deriving the fact's `y` from the canvas
  height instead left the date link 16px long, with both labels on top of each other.
- The **D11 note** in `star_schema()` is set at 17px, larger than it needs to be in the PNG.
  It is sized to survive being scaled down onto a slide; at the original 13px it was legible
  in the raster and illegible everywhere the diagram is actually shown.
